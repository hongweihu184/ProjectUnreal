这章做完有什么

两个 C++ 类 + 三个编辑器资产,构成整个战斗系统的地基。做完后:

  • 任何角色(主角/小兵/Boss)继承 BaseCharacter 就自带"战斗大脑"(ASC)和"属性表"(HP/体力)。
  • 之后所有技能、伤害、Buff 都不再写 C++,全在蓝图里配——这正是选 GAS 的理由。
  • PIE 时控制台能实时看到角色的 HP/体力数值。

5 个概念的人话版(C# 类比)

tranek 文档看不懂,是因为它假设你已经知道这些概念在解决什么问题。先用 C# 把心智模型立起来:

GAS 概念C# 类比人话解释
ASC
(AbilitySystemComponent)		挂在角色 GameObject 上的 CombatBrain : MonoBehaviour角色的"战斗大脑"。属性表、技能列表、正在生效的 Buff,全都由它持有和管理。一个角色一个。
AttributeSetclass Stats { float Health; float MaxHealth; ... }属性字段的定义。相当于 Excel 表的表头——只规定"有哪些列",具体数值存在每个角色自己的实例里。全项目唯一必须写 C++ 的部分(官方不支持蓝图创建)。
GE
(GameplayEffect)		一条配置数据:{ target:"Health", op:"Add", value:-50 }"修改属性的一条规则"。伤害 -50、体力 -20、每秒回 5 血,都是 GE。纯蓝图资产,策划改数值不动代码,这是策划的主战场。
GA
(GameplayAbility)		一个技能的协程流程:IEnumerator AttackCombo()"一个技能的完整流程":播动画 → 等命中帧 → 做判定 → 打 GE。第 4 章才开始写,本章不涉及。
GameplayTag带层级的字符串枚举:"State.Invulnerable"贴在角色身上的"状态贴纸"。伤害结算时查"有没有无敌贴纸",有就免伤。比 bool 强在:层级匹配、可在编辑器统一管理、网络同步。
一句话串起来:ASC 是大脑,AttributeSet 是它手里的属性表,GE 是改表的规则,GA 是按顺序打 GE 的流程,Tag 是流程中互相识别用的贴纸。

为什么是 FGameplayAttributeData 而不是普通 float?

这是读 tranek 时第一个看不懂的地方。原因:

  • GAS 需要监听属性变化(UI 血条要刷新)、记录 Base 值与 Current 值(Buff 加的是临时修正,卸下装备要还原)。普通 float 做不到,所以包了一层结构体。
  • 类比 C#:不是 float Health,而是 ObservableValue<float> Health——带变更事件的值。
  • 所以读写属性要用宏生成的 GetHealth() / SetHealth(x),不能直接赋值(赋值会绕过通知机制)。

数据流:一条血怎么扣

理解这条链路,本章代码每一行都知道在干嘛(命中判定部分第 4 章才做,先知道全貌):

攻击方 GA 对目标打 GE_Damage(规则:Damage 属性 +50)
  → 目标 ASC 收到,修改 Damage 属性
  → 目标 AttributeSet.PostGameplayEffectExecute() 被回调  ← 本章写的代码
      读到 Damage=50 → Health -= 50 → Damage 清零(它只是临时通道)
  → PreAttributeChange 把 Health 钳制在 [0, MaxHealth]     ← 本章写的代码
  → UI 监听 Health 变化刷新血条                             ← 第 8 章
为什么不直接让 GE 减 Health?因为伤害结算前要做事:查无敌 Tag、算防御减免、记录死亡。GE 只是"送数据的包裹",PostGameplayEffectExecute 是"拆包裹后的处理台"。这个"元属性(Meta Attribute)过一手"的模式是 GAS 伤害的标准做法。

类一 · MyAttributeSet C++

创建方式:编辑器 Tools → New C++ Class → 右上角 All Classes 搜 AttributeSet → 命名 MyAttributeSet。然后把两个文件内容替换为下面代码(也可以直接手建文件,路径 Source/ProjectUnreal/)。

MyAttributeSet.h(完整代码)

#pragma once

#include "CoreMinimal.h"
#include "AttributeSet.h"
#include "AbilitySystemComponent.h"
#include "MyAttributeSet.generated.h"

// 这个宏为每个属性一次性生成 4 个助手函数:
//   GetHealthAttribute() / GetHealth() / SetHealth(x) / InitHealth(x)
// 类比 C#:相当于自动属性 { get; set; } 的 GAS 版,但走的是通知管线
#define ATTRIBUTE_ACCESSORS(ClassName, PropertyName) \
	GAMEPLAYATTRIBUTE_PROPERTY_GETTER(ClassName, PropertyName) \
	GAMEPLAYATTRIBUTE_VALUE_GETTER(PropertyName) \
	GAMEPLAYATTRIBUTE_VALUE_SETTER(PropertyName) \
	GAMEPLAYATTRIBUTE_VALUE_INITTER(PropertyName)

UCLASS()
class PROJECTUNREAL_API UMyAttributeSet : public UAttributeSet
{
	GENERATED_BODY()

public:
	UMyAttributeSet();

	// ---- 生命 ----
	UPROPERTY(BlueprintReadOnly, Category = "Attributes")
	FGameplayAttributeData Health;
	ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)

	UPROPERTY(BlueprintReadOnly, Category = "Attributes")
	FGameplayAttributeData MaxHealth;
	ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxHealth)

	// ---- 体力 ----
	UPROPERTY(BlueprintReadOnly, Category = "Attributes")
	FGameplayAttributeData Stamina;
	ATTRIBUTE_ACCESSORS(UMyAttributeSet, Stamina)

	UPROPERTY(BlueprintReadOnly, Category = "Attributes")
	FGameplayAttributeData MaxStamina;
	ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxStamina)

	// ---- 元属性:伤害临时通道(见"数据流"一节的解释) ----
	UPROPERTY(BlueprintReadOnly, Category = "Attributes|Meta")
	FGameplayAttributeData Damage;
	ATTRIBUTE_ACCESSORS(UMyAttributeSet, Damage)

	// 属性即将变化:在这里钳制(Clamp)
	virtual void PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) override;

	// GE 结算完成之后:在这里做"拆包裹"处理
	virtual void PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data) override;
};

头文件逐段解释

代码解释
#include "...generated.h"UE 反射系统的生成头,必须是最后一个 include,顺序错了直接编译失败(新手最常踩)。类比 C# 的分部类自动生成的另一半。
UCLASS() / GENERATED_BODY()告诉 UE"这个类要被反射"(蓝图可见、GC 管理、序列化)。类比 C# 的 [Serializable] + 注册进类型系统。
PROJECTUNREAL_APIdll 导出宏,跨模块可见。类比 C# 的 public 程序集边界。
UPROPERTY(...)让字段被 UE 管理(垃圾回收/编辑器可见)。BlueprintReadOnly = 蓝图能读不能写。
FGameplayAttributeData上一节说的"带通知的 float"。
ATTRIBUTE_ACCESSORS(...)展开成 4 个函数声明。tranek 的宏,社区标准写法,照抄即可。

MyAttributeSet.cpp(完整代码)

#include "MyAttributeSet.h"

UMyAttributeSet::UMyAttributeSet()
{
	// 构造函数里的默认值,只影响"白板"状态
	// 真正的出生数值由 GE_InitAttributes 给(策划可在蓝图里随时改)
	InitHealth(100.f);
	InitMaxHealth(100.f);
	InitStamina(100.f);
	InitMaxStamina(100.f);
}

void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
{
	Super::PreAttributeChange(Attribute, NewValue);

	// 任何属性变化前都会经过这里,把 NewValue 钳到合法区间
	if (Attribute == GetHealthAttribute())
	{
		NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth());
	}
	else if (Attribute == GetStaminaAttribute())
	{
		NewValue = FMath::Clamp(NewValue, 0.f, GetMaxStamina());
	}
}

void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)
{
	Super::PostGameplayEffectExecute(Data);

	// 每个 GE 结算完都会回调这里。Data 里装着"谁打的、改了哪个属性、改了多少"
	if (Data.EvaluatedData.Attribute == GetDamageAttribute())
	{
		// 1. 读出这次伤害
		const float LocalDamage = GetDamage();
		// 2. 立刻清零:Damage 只是临时通道,不能留着,否则下次会叠加
		SetDamage(0.f);

		if (LocalDamage > 0.f)
		{
			// 3. 真正扣血(第 5 章会在这里加:查 State.Invulnerable 免伤)
			SetHealth(FMath::Clamp(GetHealth() - LocalDamage, 0.f, GetMaxHealth()));
		}
	}
}
写完自检:如果将来问"受到伤害时我的代码在哪执行?"——答案是 PostGameplayEffectExecute 里那个 if。所有伤害、回血、体力消耗,最终都汇聚到这一个函数里分流。这就是 GAS"数值逻辑集中化"的体现。

类二 · BaseCharacter C++

New C++ Class → 父类 Character → 命名 BaseCharacter。主角、小兵、Boss 以后都继承它。

BaseCharacter.h(完整代码)

#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Character.h"
#include "AbilitySystemInterface.h"
#include "BaseCharacter.generated.h"

class UAbilitySystemComponent;
class UMyAttributeSet;
class UGameplayEffect;

UCLASS()
class PROJECTUNREAL_API ABaseCharacter : public ACharacter, public IAbilitySystemInterface
{
	GENERATED_BODY()

public:
	ABaseCharacter();

	// IAbilitySystemInterface 要求的唯一函数:
	// 让 GAS 系统能通过 GetAbilitySystemComponent() 找到这个角色的 ASC
	virtual UAbilitySystemComponent* GetAbilitySystemComponent() const override;

protected:
	virtual void BeginPlay() override;

	// 战斗大脑(ASC),构造时创建
	UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "GAS")
	TObjectPtr<UAbilitySystemComponent> AbilitySystemComponent;

	// 属性表实例,构造时创建
	UPROPERTY()
	TObjectPtr<const UMyAttributeSet> AttributeSet;

	// 出生时要打给自己的 GE,在蓝图子类里填 GE_InitAttributes
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "GAS")
	TSubclassOf<UGameplayEffect> InitAttributesEffect;
};

BaseCharacter.cpp(完整代码)

#include "BaseCharacter.h"
#include "AbilitySystemComponent.h"
#include "MyAttributeSet.h"

ABaseCharacter::ABaseCharacter()
{
	PrimaryActorTick.bCanEverTick = false;

	// 类比 Unity:gameObject.AddComponent<AbilitySystemComponent>()
	AbilitySystemComponent = CreateDefaultSubobject<UAbilitySystemComponent>(TEXT("AbilitySystemComponent"));

	// 属性表也跟着角色走
	AttributeSet = CreateDefaultSubobject<UMyAttributeSet>(TEXT("AttributeSet"));
}

UAbilitySystemComponent* ABaseCharacter::GetAbilitySystemComponent() const
{
	return AbilitySystemComponent;
}

void ABaseCharacter::BeginPlay()
{
	Super::BeginPlay();

	// 出生:如果蓝图子类里填了初始化 GE,就打给自己
	if (AbilitySystemComponent && InitAttributesEffect)
	{
		// 这三行是"打一个 GE"的标准样板,以后每次手动打 GE 都这么写:
		// 1) 造上下文(谁打的、打谁的)
		FGameplayEffectContextHandle Context = AbilitySystemComponent->MakeEffectContext();
		Context.AddSourceObject(this);
		// 2) 按 GE 资产造出一份"规则说明书"(Spec),等级 1
		const FGameplayEffectSpecHandle Spec = AbilitySystemComponent->MakeOutgoingSpec(InitAttributesEffect, 1.f, Context);
		// 3) 对自己执行
		if (Spec.IsValid())
		{
			AbilitySystemComponent->ApplyGameplayEffectSpecToSelf(*Spec.Data.Get());
		}
	}
}
单机 demo 的简化说明:官方多人游戏标准做法是把 ASC 挂在 PlayerState 上(玩家死亡重生不丢战斗状态)、并开启 ASC 复制(Replication)。我们是单机 demo,直接挂 Character、不配网络,完全够用。面试时知道标准做法即可,tranek §4.1 有讲。

编辑器四步配置

第 1 步:录入 GameplayTag 根

  1. 菜单 Edit → Project Settings → 左侧搜 GameplayTags → Gameplay Tags 页签。
  2. Gameplay Tag List 点 +,依次添加三个根标签:Ability、State、Event。
  3. 子标签(State.Invulnerable 等)后面章节用到再加,先只立三根。

第 2 步:做 GE_InitAttributes(第一个 GameplayEffect)

  1. 内容浏览器新建文件夹 Content/GAS/GE/ → 右键 → Gameplay → Gameplay Effect → 命名 GE_InitAttributes。
  2. 双击打开,设置:
    • Duration Policy = Instant(立即生效,不是持续 Buff)
    • Modifiers 点 + 加 4 条,每条设置:
      AttributeModifier OpMagnitude
      MaxHealthOverride100
      HealthOverride100
      MaxStaminaOverride100
      StaminaOverride100
这一大步在干嘛:这就是"策划配数值"的标准姿势。以后想调成出生 80% 血、Boss 5000 血,都是改/新建这种 GE 资产,不碰代码。Override 是直接赋值;以后伤害 GE 用 Add -50。

第 3 步:建 BP_BaseCharacter

  1. 内容浏览器 Content/GAS/ 下右键 → Blueprint Class → All Classes 搜 BaseCharacter(我们的 C++ 类)→ 命名 BP_BaseCharacter。
  2. 双击打开,右侧 Details 面板搜 Init Attributes Effect → 选 GE_InitAttributes。
  3. 随便给个能看见的模型:选中 Mesh 组件,Skeletal Mesh 可先用引擎自带 SKM_Manny_Simple(第 3 章再换 Greystone)。
  4. Details 搜 Auto Possess Player → 设为 Player 0(让 PIE 时玩家直接控制它,验收的 showdebug 需要)。
  5. 编译保存。

第 4 步:放进关卡

  1. 把 BP_BaseCharacter 拖进关卡地面附近。
  2. 保存关卡(建议 Content/Maps/L_TestGAS)。

你一定会问的问题

Q:数值为什么一份写 C++ 构造函数(100),一份又写 GE(100)?

C++ 里的是"编译期默认值",防白板;真正生效的是 GE——因为 GE 是策划可以随时改、可以按等级缩放的资产。改数值永远改 GE,不改 C++。

Q:Damage 这个属性会显示在面板上吗?要存盘吗?

不需要。它是"元属性"——只在一次 GE 结算的瞬间存在的临时通道,用完即清零(我们代码里 SetDamage(0.f))。

Q:为什么 BaseCharacter 头文件里用 TObjectPtr<> 而不是裸指针?

UE5 的 UPROPERTY 指针标准写法,等价于 UE4 的裸 UPROPERTY 指针,编辑器里序列化更安全。照抄即可。

Q:我看 Narxim 示例里还有一大堆类(PlayerState、GameMode…),我们都需要吗?

不需要。Narxim 演示的是多人完整架构。我们的精简版:本章 2 个类,后面按需加(敌人 AI 控制器、Boss 阶段等)。少即是多,能跑最重要。

Q:写完这章,下次打开工程还要重新编译吗?

不用。编译产物在 Binaries/ 里,双击 .uproject 直接开。只有改了 C++ 才要再编译。

使用说明

本表是 Config/DefaultGameplayTags.ini 的人读版存档。ini 是唯一真源——两者不一致时以 ini 为准并修正本表。每新增标签:先写 ini → 重启编辑器 → 再在本表登记一行。

血泪规矩(错题本 P21):ini 改动后必须重启编辑器;不要在资产已引用标签的过程中改注册表——编辑器会把"无效标签"直接从资产上剥离。

Ability · 技能树

语义:"这是什么技能"。贴在 GA 的资产标签上;输入端用父标签匹配(HasAll 含父级匹配,源码已验证)。

标签含义用在哪新增
Ability根节点—第 2 章
Ability.Attack.Light轻攻击(三连击)总标签输入激活匹配(C++ OnAttackInput / BP TryActivate)第 4 章
Ability.Attack.Light.1三连击·第一段GA_Attack_Light_1 的资产标签第 4 章
Ability.Attack.Light.2/3三连击·第二/三段(待注册)GA_2/3 的资产标签第 4 章

State · 状态树

语义:"角色此刻处于什么状态"。由 GE 授予/过期移除;其他系统只读查询,永不直接改写。

标签含义授予者 → 读取者新增
State根节点—第 2 章
State.Attacking攻击中GA 激活已拥有标签 → UI/AI/其他技能查询第 4 章
State.Combo.Window连击窗口开放中GE_ComboWindow(0.5s)→ GA_2/3 的激活门槛第 4 章
State.MoveLocked移动锁定GE_MoveLock(ANS_MoveLock 区间触发)→ C++ 移动/跳跃通用闸门第 4 章
State.Invulnerable无敌帧(待注册)翻滚 GE → 伤害管线查询免伤第 5 章
State.Dead死亡(待注册)伤害结算血空时 → 死亡动画/UI第 5 章

Event · 事件树

语义:"某事刚刚发生"(瞬间信号)。发送方不认接收方,接收方不认发送方,双方只认标签。

标签含义谁发 → 谁收新增
Event根节点—第 2 章
Event.Montage.Attack.Hit攻击命中武器胶囊 overlap(Payload 带目标)→ GA 命中链第 4 章
Event.Combo.WindowOpen连击窗口开启蒙太奇单帧通知(AN_SendGameplayEvent)→ GA 打 GE_ComboWindow第 4 章

标签使用规则(本项目约定)

  1. 命名:树.系统.事件名(如 Event.Combo.WindowOpen)。不许无前缀裸标签( Combo.WindowOpen 事故,已清理)
  2. 三棵树各管各的:Ability=技能身份,State=持续状态(可查询),Event=瞬间信号(一次性)。不要把持续状态塞进 Event,反之亦然
  3. 注册流程:改 ini → 重启编辑器 → 本表登记。永不跳过重启
  4. 父子匹配:查询父标签能命中所有子标签(Ability.Attack.Light 匹配 .1/.2/.3)——连击选段靠这个
  5. 废弃标签:先从所有资产移除引用 → 再从 ini 删除 → 重启。顺序不可颠倒(P21)

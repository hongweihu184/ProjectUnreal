这份文档怎么读

每个文件分两部分呈现:先是完整原文(一个字都没省略,带行号,和 Source/ProjectUnreal/ 里的真实文件一字不差),然后是逐行翻译表——每一行配一句大白话。

空行和大括号这种"格式行"也会讲,讲一次你就知道它们是干什么的了。不需要背,看到眼熟就算达标。

先读第 0 课(十个生活比喻),再开始第 1 课。

第 0 课 · 看懂代码需要的十个概念

1. 代码就是一张"指令清单"

电脑是个极其死板、极其勤快的员工。代码就是你写给它的清单,从上往下,一条一条执行。它绝不会自己动脑筋,你写什么它做什么。

2. // 后面的话是给人看的,电脑直接无视

两个斜杠开头的叫"注释"。就像装修图纸上用铅笔写的备注——施工队(电脑)不看,只给你自己留的提示。

3. #include = "把那份文件的内容抄到这里来"

写代码经常要用到别人写好的东西。#include "某某.h" 的意思就是:把"某某"那份文件的全部内容,原样抄写到这一行来。类似写作文时"此处引用《某某文件》全文"。

4. 代码总是成对出现:.h 是说明书,.cpp 是施工队

  • .h 文件(头文件):一份说明书,写清楚"这个东西叫什么、由哪些零件组成、会做哪些动作"。只描述,不干活。
  • .cpp 文件:施工队,把说明书里承诺的每个动作,真正一步一步写出来。

5. "类"是图纸,"对象"是按图纸造出来的实物

类(class)就是一张图纸:比如"汽车图纸"写着——有四个轮子、一个方向盘、会跑。图纸本身不能开。按图纸造出来的每一辆真车,叫一个对象。我们写的 BaseCharacter 是"战斗角色图纸";游戏里主角、每个小兵、Boss,都是按它造出来的对象,各自有各自的血量。

6. "函数"是一个有名字的动作

函数就是给一串指令起个名字,方便反复用。比如 SetHealth(50):名字是"设置血量",括号里的 50 是材料。有的函数干完活会交回一个结果,比如 GetHealth() 会"汇报"当前血量。括号空着 = "不需要材料"。

7. "变量"是一个贴了标签的盒子

变量就是盒子,标签上写名字,里面装东西。比如 Health 这个盒子装着当前血量。数字会变(被打就减少),但盒子名字不变。

8. "宏"是一条"查找替换"规则

看到 #define 开头的,那是宏。意思是:"以后凡是看到 A,都当作 B 处理"。和 Word 里的"查找替换"一模一样,在编译之前自动替换。我们用它偷懒:写一遍,顶四遍。

9. "指针"是门牌号,不是房子本身

看到 TObjectPtr<某物> 或 某物*,那是"指针"——那个东西的门牌号,写着它住在内存哪个地址。要真正找到那个东西,得按门牌找过去(代码里用 -> 箭头,读作"去……家里")。

10. 虚幻引擎的"姓名牌"规矩

开头字母身份例子
U普通零件(不直接出现在游戏世界里)UMyAttributeSet 我们的属性表
A能放进游戏世界的"演员"(Actor)ABaseCharacter 我们的角色
F轻量的小数据结构FGameplayAttributeData 属性数据
I接口(一纸"必须遵守的约定")IAbilitySystemInterface
三个高频英文词:Health = 生命值;Stamina = 体力;Damage = 伤害。Max 是"最大值"的缩写,MaxHealth = 血量上限。

逐行翻译

行代码大白话翻译
1#pragma once对编译器说:"这份文件只准抄写一次"。防止被重复抄写出错。几乎所有 .h 的第一行都是它,固定套路。
2(空行)空行没有任何作用,纯粹为了"分段好看"——就像文章的换段。后面所有空行同理,不再重复。
3#include "CoreMinimal.h"把 UE 的"基础工具包"抄过来(数字处理、文字处理等基本功能都在里面)。几乎每个 UE 代码文件都要它。
4#include "AttributeSet.h"把"官方属性表图纸"抄过来——我们的图纸要在它基础上改装,先得拿到原版。
5#include "AbilitySystemComponent.h"把"战斗大脑的图纸"抄过来——第 8~12 行那个偷懒宏要用到它里面的东西。
6#include "MyAttributeSet.generated.h"把引擎自动为我们生成的文件抄过来。我们从不自己写它,UE 编译时偷偷生成。铁律:它必须是最后一个 #include,放错位置直接编译失败。
8#define ATTRIBUTE_ACCESSORS(ClassName, PropertyName) \定义一条"查找替换"规则(见第 0 课第 8 条),名字叫"属性访问器"。括号里是两个空位:类名、属性名,用的时候往里填。行尾的 \ 意思是"这行没完,下一行接着算"。
9~12GAMEPLAYATTRIBUTE_PROPERTY_GETTER(...) GAMEPLAYATTRIBUTE_VALUE_GETTER(...) GAMEPLAYATTRIBUTE_VALUE_SETTER(...) GAMEPLAYATTRIBUTE_VALUE_INITTER(...)这条规则的内容:一口气生成四个小工具函数,分别负责——拿到属性本身(GETTER = 获取器)、读数值、写数值(SETTER = 设置器)、设初始值(INITTER)。
为什么需要?GAS 规定属性必须通过这四个"正规窗口"办理,直接赋值会绕过"变化广播",血条就收不到刷新通知。每个属性都要这四个窗口,手写要写到吐,所以用宏批量生产。
14UCLASS()对引擎喊:"注意!下面要登记一个新类了!"引擎会给它办户口(蓝图里能看见、垃圾回收会管它)。
15class PROJECTUNREAL_API UMyAttributeSet : public UAttributeSet正式报名:
· class = 这是一张图纸
· UMyAttributeSet = 图纸名字("我的属性表")
· PROJECTUNREAL_API = 盖"本工程出品、对外开放"的章,别处代码才允许用它
· : public UAttributeSet = 在官方图纸基础上改装:官方已有的功能全部免费继承,只加自己的新东西
16{左大括号:"图纸正文从这里开始"。第 16 行的 { 和第 44 行的 } 是一对,中间所有内容都属于这张图纸。
17GENERATED_BODY()UE 要求的"暗桩"。引擎办户口时要往类里塞它自己的东西,这个标记告诉它"塞这里"。固定套路,照抄。
19public:"以下内容是对外公开的"——谁都可以看、可以用。
20UMyAttributeSet();挂个牌子:"本图纸有一张出厂设置单(构造函数)"。每造一个属性表对象,就先照这张单子初始化一遍。这里只挂牌,具体内容在 .cpp(第 2 课)。行尾分号 = "这句话说完了"。
22UPROPERTY(BlueprintReadOnly, Category = "Attributes")给下面那个变量办登记:
· BlueprintReadOnly = 蓝图可以读,不准改(读写分开授权,更安全)
· Category = 在编辑器面板里归到"属性"分组,好找
23FGameplayAttributeData Health;图纸上的零件一:生命值。类型 FGameplayAttributeData 是"会广播自己变化的数字"——数值一变,自动敲锣通知所有关心它的人(血条 UI 就靠这个)。GAS 属性必须用它的原因就在这。
24ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)动用第 8 行那条偷懒规则:给 Health 批量造出四个窗口——GetHealthAttribute()(拿属性本身)、GetHealth()(读血)、SetHealth(x)(写血)、InitHealth(x)(设出厂血量)。第 2 课会看到它们被使用。
26~28UPROPERTY(...) FGameplayAttributeData MaxHealth; ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxHealth)零件二:血量上限。和生命值一模一样的三行套路,只是名字换成 MaxHealth。回血不能超它、扣血不会低过 0——靠第 2 课的"安检门"用到它。
30~32UPROPERTY(...) FGameplayAttributeData Stamina; ATTRIBUTE_ACCESSORS(UMyAttributeSet, Stamina)零件三:当前体力。同样三行套路。第 4、5 章攻击、翻滚会消耗它。
34~36UPROPERTY(...) FGameplayAttributeData MaxStamina; ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxStamina)零件四:体力上限。同样三行套路。
38~40UPROPERTY(BlueprintReadOnly, Category = "Attributes|Meta") FGameplayAttributeData Damage; ATTRIBUTE_ACCESSORS(UMyAttributeSet, Damage)零件五:伤害(临时通道)——最特殊的一个。它不是角色的状态,是"快递单":别人打我们时,伤害数值先放这个位子上,我们的代码(第 2 课)取出来扣血,然后立刻撕单(清零)。
Category 里多了个 Meta(元),就是编辑器分组时标明"这是临时通道,不是正经属性"。
42virtual void PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) override;预告钩子一:"任何属性马上要变化之前,先叫我一声"。
· virtual + override = 官方图纸本来有这个钩子(空壳),我们换成自己的版本
· 材料:Attribute = 哪个属性要变;NewValue = 要变成几(前面的 & 表示给的是"原件",我们改了它外面立刻生效——安检门正需要这个能力)
· 干什么?第 2 课揭晓(剧透:把数值夹在合法范围)
43virtual void PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data) override;预告钩子二:"每条规则(GE)结算完之后,叫我一声"。材料 Data 是快递包裹:谁打的、改了哪个属性、改了多少。全游戏最重要的钩子——所有伤害、回血、耗体力,最终都在这里拆包处理。
44};右大括号 + 分号:"图纸正文到此结束"。和第 16 行的 { 配对收尾。
第 1 课小结:这张说明书宣布了三件事:① 我有五个属性零件;② 每个零件配四个正规办理窗口;③ 我在两个关键时刻安了钩子。怎么干活?下一课。

第 2 课 · MyAttributeSet.cpp(属性表的施工队)

位置:Source/ProjectUnreal/MyAttributeSet.cpp。上一课是"我承诺做什么",这一课是"具体怎么做"。

完整原文(40 行,一行不少)

 1#include "MyAttributeSet.h"
 2#include "GameplayEffectExtension.h"
 3
 4UMyAttributeSet::UMyAttributeSet()
 5{
 6	InitHealth(100.f);
 7	InitMaxHealth(100.f);
 8	InitStamina(100.f);
 9	InitMaxStamina(100.f);
10}
11
12void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
13{
14	Super::PreAttributeChange(Attribute, NewValue);
15
16	if (Attribute == GetHealthAttribute())
17	{
18		NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth());
19	}
20	else if (Attribute == GetStaminaAttribute())
21	{
22		NewValue = FMath::Clamp(NewValue, 0.f, GetMaxStamina());
23	}
24}
25
26void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)
27{
28	Super::PostGameplayEffectExecute(Data);
29
30	if (Data.EvaluatedData.Attribute == GetDamageAttribute())
31	{
32		const float LocalDamage = GetDamage();
33		SetDamage(0.f);
34
35		if (LocalDamage > 0.f)
36		{
37			SetHealth(FMath::Clamp(GetHealth() - LocalDamage, 0.f, GetMaxHealth()));
38		}
39	}
40}

逐行翻译

行代码大白话翻译
1#include "MyAttributeSet.h"先把自己的说明书抄过来——施工队当然要知道图纸上承诺了什么。
2#include "GameplayEffectExtension.h"把"快递包裹的拆包说明书"抄过来。第 30 行那个包裹 Data 的内部构造写在这份文件里。漏了它,电脑只知道"有个包裹"不知道"怎么拆",会报错(故障手册 P11 记的就是这个错,C2027)。
4UMyAttributeSet::UMyAttributeSet()"下面开始写 UMyAttributeSet 家的出厂设置单。":: 读作"……家的"。函数和图纸同名 = 这是构造函数,每个新对象诞生时自动执行一次。
5{"单子内容从这里开始。"和第 10 行的 } 配对。
6~9InitHealth(100.f); InitMaxHealth(100.f); InitStamina(100.f); InitMaxStamina(100.f);四行,调用第 1 课宏造出来的"设初始值"窗口:血量、血上限、体力、体力上限,出厂默认全部 100。(100.f 的 .f 只是告诉电脑"这是带小数的数"。)
注意:这只是白板默认值,游戏里真正生效的是策划配的 GE——改数值永远改 GE,不改这里。
10}"出厂设置单写完了。"
12void UMyAttributeSet::PreAttributeChange(...)"下面写钩子一:数值安检门。"(void = 这函数干完活不交回任何结果,纯干活。)材料:哪个属性要变、准备变成几。
13{函数正文开始,和第 24 行的 } 配对。
14Super::PreAttributeChange(Attribute, NewValue);"先让老爸(官方图纸)的版本跑一遍。"Super = 老爸。我们改装归改装,老爸的例行公事不能省。
16if (Attribute == GetHealthAttribute())安检开始:"如果要变的是'生命值'……"。if = 如果;== = "等于吗?"的提问(注意:判断相等用两个等号,一个等号 = 是赋值,写错地方是新手经典 bug);GetHealthAttribute() 是宏造出来的"属性本身的身份证",用来比对。
17~19{ NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth()); }如果第 16 行回答"是",就执行大括号里这一句:把新数值强行夹在 0 到血量上限之间。FMath::Clamp = 引擎提供的"夹子"工具,三个材料:(数值, 下限, 上限)。效果:血再扣不会变负数,再回不会超过满血。
20~23else if (Attribute == GetStaminaAttribute()) { NewValue = FMath::Clamp(NewValue, 0.f, GetMaxStamina()); }"否则,如果要变的是'体力',同样夹住"(下限 0,上限体力上限)。else if = "上一个条件不成立的话,再看看这个"。
24}安检门函数写完。如果两个条件都不成立(比如变的是伤害通道),什么都不做,直接放行。
26void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)"下面写钩子二:拆包处理台。"⭐ 全课最重要。每条规则(GE)结算完,引擎自动叫这个函数一次,材料 Data 是本次结算的快递包裹。
27{正文开始,和第 40 行的 } 配对。
28Super::PostGameplayEffectExecute(Data);老规矩,老爸的版本先跑。
30if (Data.EvaluatedData.Attribute == GetDamageAttribute())拆包检查:"这次结算改的是不是'伤害通道'?"——我们暂时只处理这一种包裹,其他(比如初始化 GE)直接放行。
读法:Data.EvaluatedData.Attribute 一层层拆开 = "包裹.里面的结算单.上面的属性名"。
31{"是伤害包裹"的处理区开始,和第 39 行配对。
32const float LocalDamage = GetDamage();"把伤害数值从通道里读出来,记在小本本上。"float = 小本本装带小数的数;LocalDamage = 本本名字("本次伤害");const = 记上就不许涂改。
33SetDamage(0.f);"立刻把伤害通道清零。"极其重要:通道是公用的,这次用完不撕单子,下次新伤害会和旧单子叠加,伤害翻倍出错。用完即撕,铁律。
35if (LocalDamage > 0.f)"如果小本本上的伤害大于 0"(网页里大于号写成 &gt;,代码里就是 >)。防御性检查:伤害是 0 就不用费事了。
36{扣血动作区开始,和第 38 行配对。
37SetHealth(FMath::Clamp(GetHealth() - LocalDamage, 0.f, GetMaxHealth()));真正扣血,一行三件事,从最里层往外读:
① GetHealth() - LocalDamage = 当前血量 − 伤害 = 新血量
② FMath::Clamp(…, 0, 上限) = 夹子夹住,防扣成负数
③ SetHealth(…) = 通过正规窗口写回去(血条 UI 立刻收到广播)
38~40} } }三层大括号依次收尾:扣血区完 → 伤害包裹处理区完 → 拆包台函数完。
将来这里加什么(第 4、5 章):查"无敌贴纸"(翻滚无敌帧)、算防御减伤、血量归零播死亡动画——全在第 30 行这个 if 里扩展。这就是 GAS"数值逻辑集中化":不管多少种伤害来源,都汇聚到这一个处理台。

第 5 课 · 串起来:这些代码在游戏里什么时候被执行

代码不是一直跑的,是被一个个"时刻"触发的。完整时间线:

【双击打开工程】
  编辑器加载我们的 dll,四份代码"待命",一行都没执行

【把 BP_BaseCharacter 拖进关卡,按 PIE 开始游戏】
  ① 角色诞生 → 执行【构造函数】(第 4 课第 5~12 行)
       关心跳 → 预装大脑 → 预装属性表
       (属性表自己的出厂单也跑了:白板默认全 100,第 2 课第 4~10 行)
  ② 角色进入世界 → 执行【BeginPlay】(第 4 课第 19~34 行)
       检查 → 开记录单 → 配执行单 → 服下 GE_InitAttributes
       属性被改成 GE 里配的值,每个属性变化都过了一遍【安检门】(第 2 课第 12~24 行)

【将来:怪物一刀砍在主角身上(第 4 章实现)】
  ③ 攻击技能对主角打一条 GE_Damage(伤害 50)
  ④ 伤害数值先落在"伤害通道"上
  ⑤ 结算完毕 → 自动触发【拆包台】(第 2 课第 26~40 行)
       认出是伤害包裹 → 读出 50 → 撕单子 → 100 − 50 = 50 写回血量
  ⑥ 血量变化广播 → 血条 UI 刷新(第 8 章)
理解这句话,你就入门了:我们写的代码,本质是往引擎的几个"固定时刻"(诞生、入场、属性要变、规则结算完)里,挂上自己定制的行为。引擎负责调度,我们负责在钩子里答题。

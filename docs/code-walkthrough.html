术语速查(读的时候不懂就回来查)

术语含义
#include "X"引入文件 X,使用其中定义的功能。
// 注释给人看的说明文字,编译器忽略。
.h / .cpp.h 声明"有什么"(类、函数、变量的名字和形状);.cpp 写"怎么做"(函数的具体内容)。
类(class)/ 对象类是类型定义;对象是按该类型创建的一个具体实例。游戏中每个角色都是同一个类造出的不同对象。
函数一段可重复调用的代码,格式 名字(材料)。GetHealth() 读血量,SetHealth(50) 写血量为 50。
变量有名字的存储位置,如 Health 存放当前血量。
宏(#define)编译前的文字替换规则,用于批量生成重复代码。
指针(T*、TObjectPtr<T>)记录对象所在内存位置的引用。通过 -> 访问该对象,如 ASC->Init()。
virtual + override父类定义了该函数,本类提供自己的实现来替换它。
const只读,不允许修改。
&(参数里)引用传参:函数内对它的修改直接影响外部原值。
if / else if条件分支:条件成立才执行大括号内的代码;else if 表示"否则再判断下一个条件"。
== / === 判断是否相等;= 赋值。
Super::调用父类版本的同名函数。
U / A / F / I 前缀UE 命名规范:U=普通类;A=可放入关卡的 Actor;F=轻量结构体;I=接口(要求实现特定函数)。
常用单词Health 生命值;MaxHealth 血量上限;Stamina 体力;Damage 伤害;Attribute 属性;Effect 效果;Ability 技能;Component 组件。

作用:定义角色的属性——生命、体力,以及伤害结算用的临时通道。

行代码说明

8~12#define ATTRIBUTE_ACCESSORS(ClassName, PropertyName) \ GAMEPLAYATTRIBUTE_PROPERTY_GETTER(ClassName, PropertyName) \ GAMEPLAYATTRIBUTE_VALUE_GETTER(PropertyName) \ GAMEPLAYATTRIBUTE_VALUE_SETTER(PropertyName) \ GAMEPLAYATTRIBUTE_VALUE_INITTER(PropertyName)定义宏:为一个属性一次性生成 4 个函数——获取属性本身、读值、写值、设初始值。GAS 要求属性必须通过这些函数访问,否则属性变化不会触发通知(UI 无法刷新)。行尾 \ 表示续行。

15class PROJECTUNREAL_API UMyAttributeSet : public UAttributeSet定义类 UMyAttributeSet,继承自 UAttributeSet。PROJECTUNREAL_API 是模块导出标记,让其他模块能使用本类。

17GENERATED_BODY()UE 要求的固定宏,引擎在此处插入反射相关代码。

20UMyAttributeSet();声明构造函数(创建对象时自动执行的初始化函数)。实现在 .cpp 第 4 行。

23FGameplayAttributeData Health;声明属性:生命值。该类型在数值变化时会自动通知监听者。
24ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)用宏为 Health 生成 4 个访问函数:GetHealthAttribute / GetHealth / SetHealth / InitHealth。
26~28UPROPERTY(...) FGameplayAttributeData MaxHealth; ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxHealth)同样三行,声明属性:血量上限。
30~32UPROPERTY(...) FGameplayAttributeData Stamina; ATTRIBUTE_ACCESSORS(UMyAttributeSet, Stamina)同样三行,声明属性:当前体力。
34~36UPROPERTY(...) FGameplayAttributeData MaxStamina; ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxStamina)同样三行,声明属性:体力上限。

MyAttributeSet.cpp(40 行)

作用:实现上面声明的三个函数——初始化、数值钳制、伤害结算。

行代码说明
1#include "MyAttributeSet.h"引入自己的头文件。
2#include "GameplayEffectExtension.h"引入 FGameplayEffectModCallbackData 的完整定义(第 26 行要用;漏掉会报 C2027)。
4UMyAttributeSet::UMyAttributeSet()构造函数的实现开始。对象创建时自动执行一次。
5{函数体开始,与第 10 行配对。
6~9InitHealth(100.f); InitMaxHealth(100.f); InitStamina(100.f); InitMaxStamina(100.f);四个属性的编译期默认值都设为 100。实际游戏数值由 GE_InitAttributes 决定,改数值在 GE 资产里改,不动这里。
10}构造函数结束。
12void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)属性变化前回调的实现开始。void 表示无返回值。
13{函数体开始,与第 24 行配对。
14Super::PreAttributeChange(Attribute, NewValue);先执行父类版本。
16if (Attribute == GetHealthAttribute())判断本次变化的属性是否为 Health。
17~19{ NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth()); }是则把新值限制在 [0, MaxHealth]:血不为负、不超过上限。
20~23else if (Attribute == GetStaminaAttribute()) { NewValue = FMath::Clamp(NewValue, 0.f, GetMaxStamina()); }Stamina 同理,限制在 [0, MaxStamina]。
24}函数结束。其他属性(如 Damage)不处理,直接放行。
26void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)GE 结算后回调的实现开始。所有伤害、回血、消耗的数值最终在这里统一处理。
27{函数体开始,与第 40 行配对。
28Super::PostGameplayEffectExecute(Data);先执行父类版本。
30if (Data.EvaluatedData.Attribute == GetDamageAttribute())判断本次结算的属性是否为 Damage(伤害通道)。其他 GE 不进入处理。
31{处理块开始,与第 39 行配对。
32const float LocalDamage = GetDamage();读取本次伤害值,存入局部变量。
33SetDamage(0.f);立即将 Damage 清零。必须复位,否则下一次伤害会与残留值叠加。
35if (LocalDamage > 0.f)仅当伤害大于 0 时才执行扣血。
36~38{ SetHealth(FMath::Clamp(GetHealth() - LocalDamage, 0.f, GetMaxHealth())); }扣血:新血量 = 当前血量 − 伤害,限制在 [0, MaxHealth] 后写回。写回会触发属性变化通知,UI 据此刷新。
39~40} }处理块结束,函数结束。

执行时机总结

代码不是持续运行的,而是由引擎在固定时刻调用:

时刻被执行的代码
角色被创建(放入关卡/游戏开始)两个构造函数:BaseCharacter.cpp 第 5~12 行(创建大脑和属性表),MyAttributeSet.cpp 第 4~10 行(默认值 100)
角色进入世界BeginPlay:BaseCharacter.cpp 第 19~34 行(施加 GE_InitAttributes)
任何属性即将变化PreAttributeChange:MyAttributeSet.cpp 第 12~24 行(数值钳制)
任何 GE 结算完成PostGameplayEffectExecute:MyAttributeSet.cpp 第 26~40 行(伤害扣血;第 4 章攻击实装后,每次被击中都会走到这里)

附录 · ATTRIBUTE_ACCESSORS 的完全展开(源码级)

关键零件是宏里的 ## 符号:文字拼接。例如 Get##Health 会被粘成 GetHealth。四个引擎宏定义在引擎文件 Engine/Plugins/Runtime/GameplayAbilities/Source/GameplayAbilities/Public/AttributeSet.h 第 428~456 行,可自行核对。

ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health) 经过两层替换 + 拼接后,等价于手写了四个函数:

生成的函数(真实展开,略有删节)说明
static FGameplayAttribute GetHealthAttribute() { static FProperty* Prop = FindFieldChecked<FProperty>( UMyAttributeSet::StaticClass(), "Health"); return Prop; }属性的"身份证"。通过反射系统按字符串名字 "Health" 查到该属性的注册信息。用于"这次变化的是哪个属性"的比对。
inline float GetHealth() const { return Health.GetCurrentValue(); }读数值:返回 Health 变量的当前值。
inline void SetHealth(float NewVal) { UAbilitySystemComponent* AbilityComp = GetOwningAbilitySystemComponent(); if (ensure(AbilityComp)) { AbilityComp->SetNumericAttributeBase(GetHealthAttribute(), NewVal); } }写数值:不直接写变量,而是走战斗大脑。属性变化的通知、钳制都在这里触发——这就是禁止直接赋值的原因。
inline void InitHealth(float NewVal) { Health.SetBaseValue(NewVal); Health.SetCurrentValue(NewVal); }设初始值:直接写变量(对象刚创建时还没有大脑可用)。注意有两个值——BaseValue(基础裸值)和 CurrentValue(经 Buff 修正后的当前值),这正是属性"不是裸 float"的原因。
替换过程回顾:我们的宏先把两个空位代入(ClassName→UMyAttributeSet, PropertyName→Health),得到四个引擎宏;引擎宏再展开为上面的函数,其中 ## 把 Get 与属性名粘成函数名。每个属性一行宏,省去手写 4 个函数。
